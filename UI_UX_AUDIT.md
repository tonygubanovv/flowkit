# Аудит UI/UX FlowKit — 03.11.2026

Цель: спокойный, предсказуемый рабочий интерфейс без случайных скачков и скрытых обязательных действий. Код приложения в ходе аудита не менялся.

Проверка: текущий локальный интерфейс в браузере при 1280×720 и 390×844, обновление страницы, мобильная шапка и кнопка меню; чтение запуска, хранения, навигации, поиска, редакторов и общих стилей. Проверка проведена на локальных данных, а не на рабочей базе пользователя. Покадровая запись холодной загрузки, большие наборы задач, реальные AI-запросы и полный drag&drop-прогон не выполнялись.

## Статус после исправлений

Аудит ниже описывает исходное состояние. После согласования внесены исправления запуска и ошибок хранения (1.1–1.3), создания проекта, завершения через редактор задачи, поиска и закрытия настроек (2.3–2.6), белой рамки выбора цвета, дубля поиска в шапке и раздельных AI-входов, состояния AI без ключа и пустых разговоров (3.1–3.3).

По новому решению пользователя мобильная и планшетная версии не разрабатываются: вместо исправления 2.1–2.2 рабочие экраны на этих устройствах заменены заглушкой. Это изменение продуктового объёма, а не заявление о готовой мобильной версии. Детали реализации и границы проверок зафиксированы в PROJECT_CONTEXT.md, раздел «Исправления по аудиту и поддержка устройств».

## 1. Сначала исправить стабильность

### 1.1. Белая область до готовности приложения — высокий приоритет

Факт по коду: index.html не содержит ранних стилей фона и сброса отступов. Пока читается IndexedDB, App возвращает отдельный загрузчик; GLOBAL_STYLES подключается только после isLoading. В этот промежуток действует стандартный отступ body и стандартный фон документа. Это конкретная причина возможного светлого края/вспышки, но сам краткий кадр не был записан.

Источники: index.html:22; src/App.tsx:677, :695; src/styles/Styles.ts:5451.

Исправление: задать минимальный тёмный фон, color-scheme, margin:0 и размеры html/body/root непосредственно в начальном HTML; загрузка данных не должна менять геометрию страницы. Критерий: при холодной перезагрузке нет светлого кадра и сдвига внешнего края.

### 1.2. Экран появляется в несколько стадий — высокий приоритет

Факт: сначала загрузчик, затем основная оболочка, затем lazy-экран с fallback=null. Каждый экран дополнительно входит с translateY/scale/fade за 220 мс. Браузер подтвердил animation fk-view-enter. Onest подключён внешним CSS с display=swap и дополнительно через @import. Возможная смена метрик шрифта добавляет ещё один источник сдвига; её вклад отдельно не измерялся. Тема сначала вычисляется из defaultData, затем из загруженного профиля.

Источники: src/App.tsx:314, :677, :802–803; src/styles/Styles.ts:5432, :5528, :5573; index.html:20.

Исправление: стабильная оболочка с резервированием места, убрать входной сдвиг экрана, одна стратегия загрузки шрифта и восстановление темы до показа основного интерфейса. Не заменять одну эффектную анимацию другой.

### 1.3. Ошибка хранения не имеет понятного пользовательского исхода — высокий приоритет

Факт по коду: loadData вызывается без catch/finally; при отказе IndexedDB isLoading может остаться true. persistAppData вызывается без обработки отказа записи. Пользователь не получает ясного сигнала, что изменения не сохранены.

Источники: src/App.tsx:323–343; src/data/AppStorage.ts:36; src/data/Db.ts:15.

Исправление: отдельные состояния ошибки загрузки и сохранения, повтор действия, возможность выгрузить текущие данные при ошибке записи. Приёмка: отказ IndexedDB не оставляет вечный загрузчик и не маскирует отсутствие сохранения. Сбой хранилища в браузере не имитировался.

## 2. Исправить незавершённые сценарии

### 2.1. Мобильная навигация не работает — высокий приоритет

Подтверждено в браузере при 390 px: нажатие меню не открывает панель. В коде sidebarOpen записывается, но сайдбар монтируется только при !isMobile.

Источники: src/App.tsx:267, :697, :722.

Исправление: один рабочий мобильный drawer с теми же маршрутами и доступом к проектам/настройкам. Не добавлять отдельный второй набор навигации.

### 2.2. Мобильная шапка перекрывает заголовок — высокий приоритет

Подтверждено скриншотом при 390 px: название проекта перекрывается кнопками поиска/фильтра. Ряд содержит меню, заголовок, настройки проекта, поиск, фильтры, AI, чат и создание. Toolbar не сжимается, заголовок nowrap. Внизу дополнительно резервируется 64 px под отсутствующую нижнюю навигацию.

Источники: src/App.tsx:718–797; src/styles/Styles.ts:2766, :2784–2813.

Исправление: на узком экране оставить заголовок и основное действие, вторичные действия собрать в меню. Название проекта не должно делить одно место с кнопками. Убрать резерв под отсутствующую панель. Горизонтальная прокрутка канбана сама по себе допустима и не является этим дефектом.

### 2.3. Новый проект не готов к первой задаче — высокий приоритет

Факт по коду: Sidebar создаёт проект с columns:[], редьюсер не добавляет колонки. openNewTask молча возвращается без первой колонки. Пользователю предлагается «Задача», но действие может не дать результата. Сам новый проект также не открывается автоматически.

Источники: src/components/Sidebar.tsx:100; src/lib/AppReducers.ts:362; src/App.tsx:351, :533.

Исправление: после создания открыть проект с минимальными рабочими колонками либо показать явный шаг настройки доски. Критерий: сценарий «создать проект → добавить задачу» проходит без поиска скрытых настроек.

### 2.4. Выполнение задачи спрятано в контекстном меню — средний приоритет

Факт: строки/карточки открываются кликом, остальные действия доступны через onContextMenu. Явной кнопки завершения нет. Это особенно неудобно на сенсорном экране и для новичка.

Источники: src/components/TaskCard.tsx:62–67; src/views/List.tsx:84–87.

Предложение: доступное меню действий задачи; основное действие «Завершить» в самой задаче. Не возвращать чекбоксы молча: их удаление было ранее согласовано.

### 2.5. Поиск не сообщает, что произошло — средний приоритет

Факт по коду: до двух символов результатов нет; отсутствие совпадений и пустой запрос выглядят практически одинаково. Результаты обрезаются до восьми без объяснения, описание ищется как HTML-строка.

Источники: src/components/modals/SearchModal.tsx:38–49.

Исправление: «Введите хотя бы 2 символа», «Ничего не найдено», указание ограничения выдачи и предсказуемая клавиатурная навигация. Поиск по тексту описания без HTML-тегов.

### 2.6. Закрытие разных редакторов ведёт себя по-разному — средний приоритет

Факт по коду: задача и заметка используют handleSafeClose; настройки закрываются через onClose по фону, без проверки несохранённых изменений. Формы не дают единого ответа на вопрос, сохранено ли введённое.

Источники: src/components/modals/SettingsModal.tsx:58; src/components/modals/NoteModal.tsx:36; src/components/modals/TaskModal.tsx:1059.

Исправление: единая политика сохранения/отмены и выхода из редакторов. Не превращать все клики в подтверждения: спрашивать только при реальной потере изменений.

## 3. Упростить композицию и состояния

### 3.1. Белые рамки имеют несколько источников — средний приоритет

Факт: выбранный цвет получает 2 px border цвета T.text (#f5f5f5). Это не подсветка текстового поля, а отдельное правило нового селектора. Есть также клавиатурный outline кнопок и собственные border/inset-кромки у поверхностей. Убирать их одним глобальным border:none нельзя: исчезнут функциональные границы и различимость элементов.

Источники: src/styles/ColorPickerStyles.ts:11; src/styles/Styles.ts:5470; UI.app.header/projectSelectTrigger и фабрики панелей.

Предложение: выбранный цвет отмечать галочкой без белой рамки; у полей оставить только статическую тихую границу там, где она нужна для формы; у клавиатурной навигации использовать один отдельный спокойный индикатор. Для конкретных белых рамок при обновлении наиболее вероятен также стартовый дефект из 1.1. По одному описанию нельзя приписать все рамки одному CSS-правилу.

### 3.2. Навигация и шапка конкурируют за внимание — средний приоритет

Наблюдение/продуктовая оценка: поиск есть слева и в шапке; «Канбан» и конкретные проекты одновременно ведут к доскам; AI-генерация и чат соседствуют как два почти равных входа. Меню проекта доступно и через шестерёнку заголовка, и в левом списке. Некоторые дубли полезны, но сейчас нет явного разделения основных и редких действий.

Источники: src/App.tsx:704–797; src/components/Sidebar.tsx:112 и далее.

Предложение: слева — маршруты и проекты; в шапке — название/контекст, одно основное действие, фильтры текущего экрана; вторичные AI/настройки — в одном понятном месте. Для большого экрана поиск можно оставить слева, для малого — в меню. Не добавлять новые счётчики, панели или декоративные секции ради «богатства».

### 3.3. Чат должен сначала объяснять готовность к работе — средний приоритет

Факт: при отсутствии API-ключа видны несколько неактивных подсказок, доступный текстовый черновик и ошибка; отправка отключена. Нет прямого перехода из этого состояния в настройку AI. Список диалогов допускает множество пустых «Новый разговор».

Источники: src/components/AiChatWidget.tsx:224–245, :328–333; src/App.tsx:959.

Предложение: спокойное состояние «Подключите AI» с одной кнопкой настроек, после подключения — рабочие подсказки. Не сохранять новый пустой диалог, пока в нём ничего нет; открывать существующий пустой вместо накопления копий. Историю и черновики сохранить.

## Рациональный порядок работ

1. **Стабильный запуск:** ранний тёмный фон/reset, одна стратегия шрифта, убрать входной сдвиг, стабильное место загрузки, ошибки хранения. Результат — перезагрузка без визуального развала и понятное состояние данных.
2. **Рабочие сценарии:** мобильная навигация и шапка, создание проекта с первой задачей, явные действия задачи, обратная связь поиска.
3. **Сокращение управления:** распределить действия между сайдбаром и шапкой; единая политика закрытия редакторов; понятный первый запуск AI.
4. **Тихие визуальные состояния:** убрать белый контур выбранного цвета и лишние кромки по фактическому экрану. Палитру, шрифт и текущие пользовательские данные не перекрашивать автоматически.

Новые фичи, новые декоративные блоки и новый редизайн до этих шагов не нужны. Критерий качества — меньше случайных состояний, меньше поиска нужной команды, отсутствие молча неработающих действий.
